# 测量陷阱清单（2026-10-30）

> 2026-10-28 到 30 这三天，我踩了 6 个坑，每一个都导致过一次错误结论。
> 这份清单把"症状 → 原因 → 上线前必做的那一项检查"写下来，用来防止同类错误。
> **所有条目都来自实际发生的错误，不是假设。**

## 陷阱 1：用了名义几何，而不是工况几何

**症状**：测出的间隙/闭合与官方数值对不上（例如间隙 17 mm vs 6.9 mm）。

**原因**：`StrictEnv(plan, cases={...})` 构造时**不会**施加工况偏移；必须再调
`env.reset(options={'case': name})` 才会把 `rung_01` 的位移写进模型。

**检查**：

```python
env = StrictEnv(plan=..., cases={case: ...}, ...)
env.reset(options={'case': case})        # 少了这一行，测的就是名义几何
print(model.geom('rung_01').pos)          # 与 manifest 里的偏移核对
```

## 陷阱 2：把"指标超线"当成"物理失败"

**症状**：看到 `cycle_endpoint_failure` 就写"撞杆/失稳/控制器不能用"。

**原因**：`cycle_endpoint_failure` 只表示**闭合超过 40 mrad**；它和"摔倒/非预期接触/关节超限"
是**完全不同的失败类型**。

**检查**：先看三项再下结论：

```python
row['time_s']                          # 113.66 = 完整跑完
row['peaks']['other'/'self'/'flight']  # 都应为 0
row['minimum_native_joint_margin_rad'] # 应为正
```

三项都正常 + 只有闭合超线 ⇒ **物理可行，指标不合格**。这两件事在真机上含义相反。

---

## 陷阱 3：注入补丁"装上了"≠"生效了"

**症状**：以为改了观测/奖励/权限，实际什么都没变。

**原因**：marker 是在**模块导入时**写的，不是在类被**实例化**时写的。
本次 `G1_ORACLE_OBSERVATION` 就属于这种：marker 正常、但 `geometry_mode` 本来就是 oracle，
补丁是空操作，于是"oracle 实验"变成了自己和自己比（两个 checkpoint 权重完全相同）。

**检查**：验证必须做到"**行为差异**"这一层，而不是"日志有记录"：

```python
# 对观测类补丁：直接比对补丁前后同一个 state 的观测向量
# 对策略类补丁：直接比对输出动作 / 权重 / 评价指标
```

## 陷阱 4：以为"24 个工况"是 24 个不同工况

**症状**：把"24 工况全过"当作鲁棒性证据。

**原因**：24 个工况只偏移 `rung_01` 一个量，其中 **16 个的位移差 <0.1 mm**。
它们测的是同一处的**重复性**。

**检查**：先打印工况的位移分布再谈鲁棒性：

```python
z = [1000*cases[c]['rung_01'][2] for c in cases]
print(sorted(z), len(set(round(v,1) for v in z)))
```

真正的鲁棒性 = **位移域 [0, D] 上全部通过的 D**（本项目中物理 ≥20 mm、指标 ≈16.1 mm）。

## 陷阱 5：复合策略的前缀/后缀，靠猜不靠验

**症状**：改了一个策略却看不到任何差别（或相反，差别大得离奇）。

**原因**：`ClosureCompositePolicy` 按 `obs[105] <= 1 - suffix_start/horizon` 在
prefix 与 suffix 之间切换。判断"闭合窗口用哪个 actor"必须算过，不能想当然。

**检查**：

```python
boundary = 1 - manifest['suffix_start_seconds'] / manifest['horizon_seconds']
clock = observations[:, 105]              # 相位钟
mask = time_s[:-1] > horizon - 2
assert np.all(clock[mask] <= boundary)    # 闭合窗口确实在 suffix
```

## 陷阱 6：拿"奖励/超参"当结论之前，先看策略动没动

**症状**：反复调奖励、调权限、调网络，结果全是"没变化"，然后开始猜"是不是观测问题"。

**原因**：先要排除"策略根本没动"。131k 步训练后
`||Δw||/||w|| = 0.166%` —— 千分之二，任何调参都不会有可测效果。

**检查**（30 秒，任何时候先做这个）：

```python
from stable_baselines3 import PPO
a = PPO.load(new).policy.state_dict(); b = PPO.load(parent).policy.state_dict()
num = sum(((a[k]-b[k])**2).sum() for k in a); den = sum((a[k]**2).sum() for k in a)
print('moved %.4f%%' % (100*(num/den)**0.5))
```

**小于 1% 就没必要继续分析效果**——先解决"为什么不动"。

## 附：一条判据层面的坑

**闭合 = `|q_终点 − q_起点|` 是相对仿真初始位姿的**。跨域（真机、不同安装）时，
姿态整体平移会让闭合等量变大，但机器人**没有摔、没有压杆**。

所以：**物理判据优先，闭合只作质量指标**（已写入《验收口径 v2》及其位移域补充）。
本项目中两者的容差差 **10 倍**（物理 5 mm vs 指标 0.5 mm）。
