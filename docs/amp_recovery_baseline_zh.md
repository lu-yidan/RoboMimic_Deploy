# AMP recovery 负载基线：与 R0/R1/R2/D4 配对比较

日期：2026-09-19。仅离线部署端仿真，无真机动作。用户提供的信息是AMP曾成功完成真机recovery，但动作偏大；本次没有取得该AMP真机测试的电机力矩日志，所以这里的数值是仿真基线，不是实测电机安全上限。

## 对齐方法

使用当前`policy/amp/config/amp.yaml`指定的`amp_0309_1.onnx`，SHA256 `e3b8fb3d6d8345981173863b5e6955f3177566a0c021e7ed62d03e048d47cc4c`。真实`Amp.enter/run`执行：96D×4帧历史，原动作映射、0.25尺度、clip±100、原PD，无额外SMP入场混合。摇杆输入全零，原速度命令滤波保留。评测适配器只同步角速度字段并接入统计接口，不改策略动作。

模型、四方向各16个程序化低位初态、零初始速度、20秒时长、2ms物理步/20ms控制步、CPU MuJoCo3.2.3、外层力矩限幅与上一轮R系列配对评测相同。初始20ms保持测得关节位置，然后首次控制更新，与原评测一致。保留AMP自身PD，比较的是“实际部署策略及其控制参数整体”，不是只换网络权重的单变量实验。AMP髋pitch Kp约99.1，SMP约40.18；腕部增益也不同。

未运行完整交互FSM、DDS或真实电机。AMP配置虽有safe_tilt_threshold字段，但当前Amp.checkChange没有按它自动退出；本次未人为加入倾斜退出。外层使用部署MuJoCo配置的力矩限值，力矩来自仿真实际qfrc_actuator。

## 用户要求的三个指标

每条轨迹先在所有物理子步、所有关节上取绝对峰值，再对64条轨迹取P95。功率为单关节`abs(tau*dq)`，不是全机功率总和，也不是电池电功率。

|策略|力矩峰值P95 N·m|关节速度峰值P95 rad/s|功率峰值P95 W|
|---|---:|---:|---:|
|**AMP baseline**|**139.00**|**37.87**|**1720.53**|
|R0_9500|99.85|14.43|350.31|
|R1_9999|131.47|12.00|488.33|
|R2_9000|101.64|11.02|496.37|
|D4_9999|139.00|16.02|912.15|

四个候选在这三个全身汇总指标上都没有超过AMP，D4力矩与AMP同为139Nm饱和上限。饱和上限会掩盖控制器“想施加更大力矩”的程度，不能仅凭相同峰值判断负载相同。R0功率约AMP的20%，D4约53%；这不意味着所有关节都更轻松。

AMP的37.87rad/s主要由右腕roll贡献；功率主要由膝和髋贡献。因此拿AMP的全身最大值统一给腰、踝、肩当作阈值，会放过局部风险。

## 恢复表现与统计解释

AMP 64/64达到头高≥1.15m、直立度≥.93，首次直立时间中位数1.34秒；57/64至少完整稳定1秒，只有9/64满足原严格连续稳定10秒。R0/R1/R2/D4均64/64满足10秒条件。

AMP严格10秒分方向：仰卧0/16、伏卧3/16、左侧0/16、右侧6/16。部分轨迹是站距/姿态/静止门槛不满足，并非没起身；不能把9/64表述为“只有9次能recovery”。也不能为AMP临时放宽指标再与R系列原指标混用。

所有64条均计入负载统计，包括未满足严格站稳的轨迹；AMP64条都曾达到直立，因此不是只有成功子集才统计。四候选和AMP在本批20秒中都未触发“首次直立后头高<.65m或直立度<.5持续0.2s”的再次倒下判定，没有数值不稳定。该规则不覆盖所有摇晃、踩踏或冲击，且这里没有压板，不回答D4压板下会不会复跌。

## 如何使用AMP安全参考

可以把用户已验证的AMP作为相对负载上限筛选基线，但应同时看：

1. 同关节力矩/速度/功率P95，以及个别极端轨迹的最大值。
2. 连续高力矩、高功率时间和饱和占比，尤其腰、髋、膝、踝；P95峰值本身不描述热负载。
3. 成功率、再次倒下、非足/头部冲击、自碰撞及坐起动量依赖。
4. 同地面、同初态的真实电机日志。低于AMP是比较性证据，不是额定硬件安全证明。

用户可以选择把“超过AMP”设为拒绝条件；反过来“没超过AMP”不能自动当作安全批准。AMP评测未修改部署控制参数；随后按用户要求，SMP默认profile设为`ft_r0_9500`。
