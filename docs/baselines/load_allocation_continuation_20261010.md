## 控制器改动

接触力 QP 原目标仅惩罚接触力偏离预设值。现在增加电机力矩使用率的平方惩罚：

`0.5 * ||f - f_goal||² + 0.5 * λ * ||D⁻¹ (required_joint - J_joint f)||²`。

`D` 为各关节原生电机力矩上限，组合方案 `λ=10000`。浮动基座动力学等式、原电机限矩、单向接触及摩擦锥约束保持不变。这是全电机归一化力矩代价，不是保证全程最大使用率低于某阈值的硬约束。

同时区分换杆与收尾阶段：换杆时保留原腿部加速度反馈增益 100；进入 `final_center` 后，在 3 s 内平滑增加至 300，并维持到周期结束。手臂和腰部反馈保持 100。下一周期的 `settle` 阶段在 3 s 内恢复到 100，再进入换手。对应阻尼为 `2*sqrt(kp)`。这不是直接把电机 PD 参数设成同样的数值。

独立配置为 `deploy_mujoco/config/mujoco_climb_cycle_optimized.yaml`。原 `mujoco_climb_cycle.yaml` 保留零力矩权重、原腿部增益，便于对照；不覆盖历史结果。

## 连续周期的验证方法

`tools/repeat_climb_cycle.py` 先检查原参考关节姿态闭合，再按照墙倾角将第二周期平移一层。时间严格递增，边界不重复时间戳；保留原有起始稳定段，并对整个两周期参考重新进行场景碰撞检查。参考为 `outputs/compact_two_cycle_plan_v1/plan.npz`，总长 218.36 s。

实际执行在同一个 MuJoCo 状态和同一个控制器实例中连续推进，不在周期边界设置 qpos、qvel 或恢复检查点。运行器依据 `cycle_ends_s` 分别检查每周期最后两秒的高度、四点承重、对应杆号和关节闭合；独立审核还分别检查末端误差、姿态和速度。缺少完整两秒记录、第一周期失败或杆号错误都不能被第二周期最后一帧掩盖。

新增测试覆盖未闭合参考拒绝拼接、边界没有额外跳变、目标累计升高 50 cm、缺失日志拒绝验收、错误横杆/缺失支撑拒绝验收，以及力矩分配降低归一化力矩且不改写仿真状态。仿真时长默认读取参考末尾，避免两周期被旧 200 s 上限截断。

首轮完整两周期试验 `compact_two_cycle_dynamic_v1` 在 161.37 s 的第二次左脚卸载处停止，原因是 OSQP 在增大迭代上限后仍未收敛。第一周期的末态检查通过；全程没有额外支撑、自碰撞或净空摆动碰撞。它不能作为两周期成功证据。

`compact_two_cycle_failure_diagnostic_v1` 从最后记录状态重现同一时刻的失败，并保存 `failure_state.npz` 与完整 `failed_force_qp.npz`。HiGHS 独立检查证明该 QP 约束仍可行，最大约束误差约 1.55e-14；这次迭代失败不能解释为物理承重必然不可行。

为此加入备用路径：仅在 OSQP 重试后仍返回低精度/迭代上限状态时，用线性可行性求解得到种子，再由 SLSQP 优化**同一个**凸二次目标，沿用全部原约束；解必须有限、报告成功且全约束残差小于 1e-5，否则仍失败。没有增加力矩上限或把约束软化。新增真实失败 QP 回归测试，以及不可行问题必须拒绝的测试；全套增至 27 项。备用求解的最坏耗时尚未完成实时性验证。

`compact_two_cycle_tail_diagnostic_v2` 从检查点继续到 218.36 s，第二周期末态通过运行器及独立复核判据，备用求解使用 4 次；由于未从初态连续运行，整体仍判失败。随后 `compact_two_cycle_dynamic_v2` 从 0 开始完整复跑并通过，才作为连续两周期成功证据。

## PowerShell 复现

以下依赖已有本机冻结模型包与参考；每次输出目录必须不存在。

```powershell
cd D:\G1Climbing\external\RoboMimic_Deploy

# 改进后的单周期：运行、独立复核、原速与 4 倍速录像
.\tools\run_climb_cycle.ps1 -ConfigName mujoco_climb_cycle_optimized -OutputDir outputs/my_optimized_cycle

# 连续两周期：自动按参考运行到 218.36 s，周期之间不重置
.\tools\run_climb_cycle.ps1 -ConfigName mujoco_climb_cycle_optimized `
  -Plan outputs/compact_two_cycle_plan_v1/plan.npz -OutputDir outputs/my_two_cycles

# 重新构造并审核两周期参考
$env:OPENBLAS_NUM_THREADS = '1'
$env:OMP_NUM_THREADS = '1'
.\.venv\Scripts\python.exe tools\repeat_climb_cycle.py `
  --source outputs/compact_cycle_plan_v13/plan.npz --count 2 --out outputs/my_two_cycle_reference

# 对照：原控制参数、相同紧凑参考
.\tools\run_climb_cycle.ps1 -ConfigName mujoco_climb_cycle -OutputDir outputs/my_previous_controller
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

配置、运行源码、参考副本、逐阶段记录、50 Hz 状态、2 kHz 碰撞力峰值及独立审核均保存在各自输出目录。`outputs` 中的本机资产不随 Git 自动分发。本轮是固定场景、已知杆位置、仿真真值状态反馈的控制基线；未训练策略，也未完成感知误差或扰动鲁棒性验证。
