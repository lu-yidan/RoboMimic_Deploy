# 2026-10-24：收尾片段课程训练准备

## 目的与统计口径

原完整周期长 113.66 秒，收尾阶段只有 14 秒。相同 98,304 个动作步的训练，完成的完整回合通常只有 16 个，最高杆约 4 个。新方案从已选定父策略实际连续运行到 99.66 秒的状态开始，每回合只学习最后 700 步，预计可显著增加收尾回合数。

这是训练重置分布和部署策略组合的改变，不是单因素奖励试验。训练回合只称“收尾片段回合”，不可称完整爬升成功。

## 实现边界

前缀缓存必须从时间零连续执行已审计父策略的动作得到，保留 MuJoCo 物理状态、接触状态、残差滤波、控制器接触历史、累计约束检查等。重置时创建新的环境副本，不覆盖正在运行的轨迹。

第一版直接序列化失败：运行中的 OSQP 求解器无法 pickle。`closure_prefix_cache_20261024_v1` 已停止且标记不可用，残留压缩文件不是有效训练数据。

第二版只在新副本中清空 OSQP 求解器缓存，保留其余状态；因此训练副本会重建 QP 求解器，不能预先声称与连续控制逐位一致。准入要求完整后段与原连续轨迹比较，位置最大差 ≤1e-7、速度 ≤1e-5、力矩 ≤1e-3、观测 ≤1e-5，且终止原因和成功标签一致。原连续分支必须精确复现保存轨迹。该误差界只约束缓存机制，不修改任务成功标准。

缓存是带哈希校验的可信本地产物，含大体积 MuJoCo 模型，不随发布包上传。初版每个训练进程只保留一个工况模板和一个活动副本；该方案出现原生内存增长，后续修复见下文。

## 完整周期验证

部署组合在 99.66 秒之前使用冻结的原父策略，之后使用训练得到的收尾策略。切换依据原观测的剩余时间分量。五条既有轨迹已验证切换发生在第 4,983 个动作步。

最终评估使用普通完整周期环境，从时间零运行到 113.66 秒，完全不读取训练缓存。独立审计按两段策略分别重建动作，并要求前段七组数组与原父策略记录精确一致。训练新增收益只有在此完整验证中通过才成立。

## 准入状态

缓存第二版正在构建，课程训练尚未启动。只有缓存完整延续检查、重复重置检查、已完成探索对照的审计均通过后，协议准备器才允许冻结并启动课程训练。

## 准入完成与训练启动

最终有效缓存为 `outputs/closure_prefix_cache_20261024_v4`。第二版因逐步重复解压轨迹造成低效而停止；第三版补充发现嵌套的接触历史控制器也持有 OSQP 缓存。第四版在副本中重建全部三个求解器缓存，并一次加载轨迹数组，未改变预先规定的误差门槛。

五个工况全部通过完整延续检查。最高杆后段最大位置差约 1.95e-14、速度差约 7.65e-13、力矩差约 1.68e-12，远低于门槛。连续原分支对保存轨迹的五类比较最大差均为零。随后五工况重复重置与首步检查通过；不能将这些浮点级差异描述为重启求解器后逐位相同。

`closure_curriculum98304_20261024_v1` 已开始四进程训练，共 98,304 个后段动作步，种子 20261023，原父策略/优化器、质量奖励及收尾腿部探索规则不变。每个回合从 99.66 秒开始，正常完成为 700 步。

所有完成的最高杆收尾回合（包括失败）保存在训练输出内的 `suffix_records_worker_*`，含观测、动作、状态、力矩、原奖励与新增奖励，以及源缓存哈希。这些是带探索的训练片段，仍需从零复核才能称完整动作证据。

训练结束自动运行完整五工况组合策略评估、动作重建审计和前段七数组一致性审计。原发布版本保持不变。


## 原生内存故障与修复验证

初次训练在约 77,824 步因工作进程原生内存分配失败中断，不能计作完成 98,304 步。保留检查点 `checkpoint_additional_73728.zip`、108 个完成的片段回合及最高杆轨迹；最高杆完成的 22 个片段均未成功。未生成最终五工况评估，不用于最终对比。

显式清理求解器缓存和 Python 引用循环仍未解决问题：50 次重置的工作集从约 2.44 GiB 增至 17.06 GiB，失败证据保存在 `closure_reset_memory_gate_20261024_v1`。

第三版环境 `training/closure_curriculum_env_v3.py` 保留五个可信模板，复用一个模型及四个 MuJoCo 数据缓冲区，使用安装版本的原生 `mj_copyModel` / `mj_copyData` 恢复新回合。只在训练新回合开始时恢复；评估从零连续运行，禁止途中恢复。Python 控制器历史仍从模板复制，三个 QP 缓存仍按已验证规则重建。

50 次轮换工况重置后，工作集约 2.94 GiB，稳态增长 40 KiB；首步位置/速度对照全部通过。该结果仅证明单进程短期压力检查，不代替四进程完整训练。完整收尾延续检查正在执行，通过后从原父策略重新跑完整预算，不把中断前样本混充新试验。

## 价值网络校准

仅拟合旧确定性轨迹的第一版价值网络，虽训练集误差很小，却在探索轨迹上更差，已明确排除。

重新采集冻结父策略的 30 个带探索片段，事先按每工况 4 个训练、2 个验证整回合划分，共 21,000 步。五工况共 24/30 片段通过，最高杆 0/6。第二版只拟合价值头，冻结动作网络和特征；验证均方误差从 1163.60 降至 0.1373。验证集参与模型选择，因此不能称独立测试集，更不能据此声称攀爬成功率提高。该模型尚未用于正式对比训练。


## 修复后完整训练已完成

`closure_curriculum98304_20261024_v2` 从原父策略重新完成 98,304 步，训练墙钟 707.88 秒，140 个完整收尾片段。最高杆 28 个片段全部失败；完整周期确定性评估尚在运行，不能据训练统计宣布最终五工况结果。

四进程训练越过原故障位置并完成预算，原生缓冲区复用方案已通过本轮长时间运行。此前中断实验不合并进该预算。PPO 日志初始化继承了父检查点的滚动 episode buffer，前期 `ep_len_mean` 可能混有旧完整周期；当前片段回合统计以 callback/Monitor 和独立轨迹为准。

复现新目录示例（仓库根目录 PowerShell；环境、协议和缓存必须保留）：

```powershell
.\.venv\Scripts\python.exe -m tools.train_closure_curriculum_v2 --protocol outputs/closure_curriculum_protocol_20261024_v2/protocol.json --weight 0.1 --output outputs/closure_curriculum_reproduce_new
```

脚本拒绝覆盖既有目录，完成后自动评估五工况并审计。一次训练消耗约 13 GiB 以上内存，缓存文件较大；本机已通过四进程运行，不据此保证其他机器相同资源表现。
